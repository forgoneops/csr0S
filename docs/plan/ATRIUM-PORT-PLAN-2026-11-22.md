## Rules every step follows
0. **The Lego rule** (Konrad, 2026-11-23): fully modular; the whole UI, frontend and backend, can be rebuilt block by block, because blocks meet only at written contracts (phase 9). See `ARCHITECTURE.md`.
1. Behaviour from Off Grid, look from the prototype, nothing invented: a page shows real data or says it has none.
2. Desktop and phone get the same functions. Polish and English. 44 px targets. Tint, not fills. Our icons and controls only.
3. A step is done when a browser run on the real core passes, not when the code is written.
4. A change touches one module; if it needs to touch two, a contract is missing and gets written first (phase 9).
5. **Two readings**: everything the system writes is structured for AI and summarised for people in a few bullets (diffs as bullets, raw one tap deeper); nobody should have to read a long text to decide (plan 11.9).
6. **Beginner first, advanced on demand** (Konrad, 2026-11-23): Caesar is meant to be advanced, but a new user who finds it intuitive stays and makes it their base. The default view is simple and plain-worded: one obvious way to start a chat, a short first run, empty states that say what to do next, advanced features (layers, modules, policy, Core unlocked, multi-agent routing) one step deeper and revealed when needed, never in the way. Measured by audit 2: clicks from first load to a first answer, menu entries on the first screen, unexplained terms, and whether a new person can finish the first task without documentation. This is what the Visual and Simple switch (8.7) and the autonomy defaults (11.4) serve.
7. Commits name explicit paths and go to `shell/*` or `fix/*`, never `main`. Nothing outward without Konrad's yes.
