# Build register: every requirement, its step, its test, its status

Purpose: nothing Konrad said can slip. Each requirement has an id, its source, the plan step that delivers it, the acceptance test, a status and the evidence link. `bun tools/plan-check.ts` fails when a requirement has no step, a step has no requirement, an acceptance cell is empty, or a row is `done` without evidence. Run it before every milestone report and in the nightly check. The plan is `POST-PROMO-BUILD-PLAN-NATIVE-AND-SYSTEM-2026-11-21.md`; steps below use its ids.

Statuses: `open`, `doing`, `blocked`, `done`, `dropped` (dropped needs a note and Konrad's word). Update status and evidence in the same commit that delivers it.
