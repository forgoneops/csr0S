## Contract

- `GET /api/engines` -> `{ engines: [{ id, label, health: { ok, detail }, models }] }`.
- `GET /api/chat/sessions` -> newest first.
- `POST /api/chat/sessions { engine, model?, title? }` -> 201; 400 for a missing or unknown engine.
- `GET /api/chat/sessions/:id` -> `{ session, messages }` ordered by `seq`.
- `POST /api/chat/sessions/:id/turns { content, model? }` -> `text/event-stream`:
  `meta` (`sessionId`, `userMessage`, `assistantMessageId`, `engine`, `model`), `delta` (`text`),
  `error` (`message`, engine failure only), `done` (`message`, `status` = `complete|error|stopped`).
- Refusals happen before anything is written: 404 unknown session, 400 empty content,
  409 `engine-unavailable`, 409 `no-model`, 409 `busy`.
- The request abort signal and the stream `cancel()` both abort the `AbortController` passed to
  `adapter.stream`, so Stop cancels the upstream HTTP request. The partial reply is persisted in a
  `finally` block with status `stopped` (client abort) or `error` (engine failure).
- Ollama is offered only when S2 detection says the binary answers (`probe.ok`), then its
  `/api/tags` answers. `health()` never throws; a stopped daemon reads `not answering`.

## Gaps

1. **No real Ollama run.** The adapter is tested against injected NDJSON and the UI against a fake
   HTTP endpoint; a real model was not installed on this machine, so the end-to-end path with a
   real Ollama is unverified.
2. **No component tests.** The SSE parser, Stop and draft restore are covered by the type check,
   the build and the browser pass, not by unit tests.
3. **Console channel not observed.** HTTP/API behaviour was observed; browser console errors were
   not captured.
4. **Server detail strings are English.** `not detected` / `not answering` come from the server;
   the UI maps error codes to translated text, but these details stay English.
5. **Failed first send leaves an empty session.** If session creation succeeds and the turn is
   refused, the empty session stays in the list.
6. **Approvals are display-only.** No approve/settle endpoint or action yet, as specified.
7. **No delete or rename of sessions.** Not in scope for S3.
