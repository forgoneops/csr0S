## 1. What this step delivers

A thin Rust shell in `src-tauri/`. The UI stays the React web app served by a gateway and the logic stays the Bun
core; the shell adds only what a browser cannot: one window with saved geometry, the connection picker and offline
page, single instance, deep links, and starting a local core on demand.

| Requirement | Where | State |
|---|---|---|
| one window, saved size and position | `src-tauri/src/window.rs`, `logic/src/geometry.rs`, `src/config.rs` | written, clamps tested |
| loads the gateway URL chosen in the picker | `lib.rs` (`connect`), `window.rs` | written |
| gateway registry: `This device` first, remote only when added | `logic/src/picker.rs` | written, 10 tests |
| local core started on demand, killed on exit, never twice | `src-tauri/src/core_proc.rs` | written |
| offline page naming the gateway that is gone | `src-tauri/ui/*` | written, strings tested |
| single instance, second launch focuses (no second window) | `tauri-plugin-single-instance` | written |
| deep links inert: focus the picker, never navigate or add a gateway | `logic/src/deeplink.rs`, `lib.rs` | written, 2 tests |
| safe external links: cross-origin navigation denied, never handed to the OS browser | `logic/src/navpolicy.rs`, `window.rs` | written, 6 tests |
| tray **off by default** | `src-tauri/src/tray.rs`, `config.tray_enabled = false` | written, unbuilt |
| pinned crates, `Cargo.lock` committed | `src-tauri/Cargo.toml`, `src-tauri/Cargo.lock` | done |

**Not in N1 on purpose:** no HUD overlay (N3), no global shortcuts (N2), no notifications, no packaging (N5), no
second window of any kind.

## 2. Measured constraints that shaped the code

- **Tray icons need `image-png`.** The tray reads the bundled PNGs through `tauri`'s `image` feature; the crate
  enables `tray-icon` and `image-png` together, and the tray is only constructed when the config says so.
- **No transparent always-on-top click-through window.** That shape panics in tao 0.37.3 (`event_loop.rs:459`) on
  this class of machine, so the overlay is N3 (Quickshell or a layer-shell panel), not a Tauri window. The shell
  never sets `transparent`, `always_on_top` or `ignore_cursor_events`.
- **The Tauri crate was built here, without touching the system.** `cargo` went into `~/.cargo` (rustup, minimal
  profile) and the `-dev` packages into `~/.local/n1-devdeps/root` (debs unpacked by `dpkg-deb -x`, no `sudo`); a
  two-line `pkg-config` wrapper points at them. That was enough to **type-check and link** the shell; it is not enough
  to **run** it, because WebKitGTK spawns `WebKitNetworkProcess` from a path compiled into the library
  (`/usr/lib/x86_64-linux-gnu/webkit2gtk-4.1/`) which only a system install (or root) can provide. The 20 s smoke run
  therefore stays on the Lenovo.
- **`std::net` cannot do TLS.** An `https://` gateway therefore gets a TCP-connect health check (online, no HTTP
  status) instead of `GET /api/health`; a `http://` loopback gateway gets the real health request. Adding TLS means
  a new dependency, which is an N4 decision (the local gateway is loopback, so N1 pays nothing for it).

## 4. Behaviour and security

**Startup.** Load `config.json` from `app_config_dir()`, build the registry (`This device` = `http://127.0.0.1:4410`
or `CAESAROS_LOCAL_GATEWAY`), create the one window at the clamped saved geometry, build the window menu
(`Connection…`, `Quit`), create the tray only if enabled, register deep links, then probe the selected gateway on a
worker thread. Online: the worker navigates the window to that gateway. Offline: the bundled page stays up and polls
`get_shell_state` every 700 ms while `status.kind` is `checking`.

**Local core on demand.** Started only when the local gateway is selected *and* nothing answers there. Discovery
order: `CAESAROS_CORE_BIN` → `caesaros-core` next to the executable → `CAESAROS_CORE_DIR` containing
`core/server.ts` (run with `bun core/server.ts`) → the current directory containing `core/server.ts`. Nothing points
at the owner's paths. Only a loopback gateway is ever started; only a child this shell started is ever killed; the
core gets `CAESAROS_HOST=127.0.0.1` and `CAESAROS_PORT` from the gateway URL.

**IPC.** Seven commands, all returning the same `ShellState` JSON documented in `src-tauri/ui/app.js`. Each command
first checks `ipc_allowed(webview.url())` and refuses anything that is not the bundled page, so the gateway's own
pages cannot reach the shell even if a capability were misconfigured. The capability file grants `core:default` to
window `main` and no `remote.urls`, so guest content has no IPC door at all.

**Navigation.** `on_navigation` allows the shell origin and the selected gateway origin, nothing else. A denied
navigation is logged and dropped: the shell never opens the OS browser by itself, so a link inside guest content
cannot hand a URL to the desktop session.

**Deep links.** `caesaros://…` only focuses the window and shows the picker. `classify()` has no navigate outcome, so
a crafted link cannot point the shell at an arbitrary address; the tests pin that.

**Config** (`~/.config/os.caesaros.shell/config.json`): remotes, selected id, window geometry, `tray_enabled: false`,
`locale: null`. Saved atomically; a broken file is logged and left on disk untouched (never deleted).

**Address rules** (tested): `http`/`https` only, no credentials, no fragment, host required, port 0 rejected, plain
`http` only to loopback (`localhost`, `127.0.0.0/8`, `::1`). A remote gateway must be `https`.

  nothing was built. That is the designed behaviour for a machine that cannot run the shell; it is not a pass.

## 6. What is NOT verified, and how the Lenovo closes it

The window, tray, menu, navigation policy and the 20 s smoke run have not run anywhere: this VPS can compile and link
the shell but cannot spawn WebKit's helper process (see §5). Rust unit tests, type check, link, the bundled page and
the strings are verified; the part a person sees is the Lenovo's. On the Lenovo (Hyprland, webkit2gtk 2.54, cargo 1.100):

```bash
# 0. the dev packages (sudo: this needs Konrad's yes once)
pkg-config --modversion webkit2gtk-4.1 javascriptcoregtk-4.1 gtk+-3.0 libsoup-3.0 || \
  sudo apt install libwebkit2gtk-4.1-dev libjavascriptcoregtk-4.1-dev libgtk-3-dev libsoup-3.0-dev
# 1. the branch
git -C /path/to/caesaros.git worktree add ~/caesaros-n1 native/n1    # or fetch the branch
# 2. tests and build
cd ~/caesaros-n1/src-tauri && cargo test -p caesaros-shell-logic && cargo build
# 3. the smoke test (build + 20 s alive)
cd ~/caesaros-n1 && tools/n1-smoke.sh 20
```

Then look at, in order: (a) the window opens at 1280x840 and reopens at the size and position it was closed with;
(b) the picker page lists `This device` first and nothing else; (c) with nothing on `:4410` the offline panel names
that gateway and says nothing is hidden; (d) `CAESAROS_LOCAL_GATEWAY=http://127.0.0.1:4410` plus a real core makes
the shell open the web app; (e) a second launch focuses the existing window instead of opening another; (f)
`xdg-open 'caesaros://open'` brings up the picker; (g) a link to another origin inside the gateway page is refused and
no browser opens; (h) no tray icon appears (it is off by default); (i) closing the window quits the app and the core
child it started is gone.

If (a)–(i) pass, N1 is done; if something fails, the failure is in the shell, not in the web app, and belongs back
in this branch.

## 7. Gaps and next steps

- **First compile on the Lenovo.** Expect small API fixes; the risky spots are the menu builder calls, the tray
  builder and the deep-link registration, all of which were matched to the vendored sources by reading them.
- **The `https` health check is a TCP connect only** (see §2). N4 decides whether to add a TLS crate.
- **`caesaros-core` binary does not exist yet.** N1 can start `bun core/server.ts` from a checkout; packaging the
  core as a sidecar is N5.
- **The picker has no route back once the gateway page is loaded** except the window menu `Connection…` (and a
  second launch with `--picker`). The engine chip (S1/R08) should later call `open_picker()`; the command already
  exists and is guarded.
- **The icon is a placeholder** (flat dark square). The icon pack is Agrippa's and swaps without code (packs rule).
- **Polish wording** in `ui/strings.json` has not had a native review; Varro's N6 QA matrix should include it.
- **No PWA or web-app change** was made here, so the web build and the core are untouched by this branch.
