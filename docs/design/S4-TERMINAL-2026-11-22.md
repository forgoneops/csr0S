Branch `shell/s4-terminal`, cut from `shell/bootstrap` at `9ba3e21`. Nothing deployed, nothing
restarted outside this worktree, no `main`, no push. Work folder: `~/caesaros-s4` (a git

Delivers requirement **R11** and the terminal half of **R40**.

## What it is

One terminal host, mounted once at the shell root, with three placements: bottom pane, right side,
tab. Hiding the pane hides it, it does not close it: the xterm buffer and the shell keep their state,
and the placement is remembered. The pane opens only when the person opens it; a tool, a module or a
shortcut cannot bring it up by itself (the zone rule).

The behaviour reference was the old prototype `~/caesar/docs/design/prototype/caesaros-new/index.html`
(read, not copied): its `termHtml`/`shell()` handlers show one terminal that is bottom-docked, can be
side-docked, can be opened as a tab, toggles with Ctrl+`, and keeps running when hidden. The
implementation here is our own: React + xterm.js on the client, a Bun PTY on the server, no prototype
code.

## Core (`core/terminal.ts`)

The terminal is core code, not a module page: it is a shell placement, and a WebSocket upgrade has to
happen at the server. `core/server.ts` wires `useTerminal(app)` before the `/api/*` catch-all and
serves the upgrade from `Bun.serve`.

| Piece | Rule |
|---|---|
| Edition | `terminalOff()` is true for `CAESAROS_EDITION=standard` and `consumer`: the routes answer 404 and no shell is started. The default build is the owner build. |
| Principal | `terminalGate()` accepts `operator` only. An agent token, an anonymous request and a PIN never open it (no PIN exists, R27). A token that is presented is refused even when the request looks like a browser. |
| Address (D5) | loopback, RFC1918, link-local, IPv6 ULA/link-local and the tailnet range `100.64.0.0/10` only. A public peer is refused; sign-in off loopback stays open and is not guessed at. |
| Host | the existing DNS-rebinding guard applies (`knownHost`), so a rebound name cannot reach the terminal. |
| Upgrade | the WebSocket also accepts a **same-origin `Origin`** as the browser's proof, because a WS handshake does not always carry the `Sec-Fetch-*` metadata a fetch does. A cross-origin page cannot borrow the operator's socket, and a presented token still loses. |
| Audit | one row when a session opens (`seen`), written before the shell starts (if the row cannot be written, no shell starts), and one when it ends (`done`, with the reason). |
| Idle timeout | `CAESAROS_TERMINAL_IDLE_MS`, default 15 min. Input and resize count as activity. A 30 s sweeper (`unref`'d) closes idle sessions. |
| Bounds | at most 4 sessions, backlog 64 KiB per session, resize clamped to 2..400 cols and 2..200 rows, control messages over 256 KiB dropped. |
| Hidden | a dropped viewer leaves the shell running and its newest output in the bounded backlog; the next viewer gets a `ready` frame and the backlog, then live bytes. |

Wire protocol, one socket per session:

- client → server (text): `{"t":"in","d":"..."}`, `{"t":"resize","cols":N,"rows":N}`, `{"t":"ping"}`
- server → client: text `{"t":"ready",id,cols,rows,idleMs}`, `{"t":"exit",reason}`, `{"t":"pong"}`; raw
  binary frames are PTY output

HTTP: `GET /api/terminal` (state), `POST /api/terminal/sessions` (open, audited, capped),
`DELETE /api/terminal/sessions/:id` (end), `GET /api/terminal/ws?id=…` (upgrade).

## Client (`web/src/terminal/`)

| File | What it does |
|---|---|
| `machine.ts` | the placement state machine as pure data: `show/hide/toggle/place/next-placement`, the tool-origin drop, and the phone fit (right → bottom). |
| `state.tsx` | one reducer for the shell; reads `matchMedia("(max-width: 760px)")`. |
| `TerminalHost.tsx` | the one host: one xterm instance for the life of the shell, fit addon, resize → `resize` frame, copy/paste buttons, End, hide; reconnects a dropped socket and replays the backlog; colours read the theme tokens. |
| `terminal.css` | the three geometries, 44 px targets, the phone drawer above the five-item bar. |

The pane is opened from the topbar terminal button or `Ctrl+\``; the placement control in its header
moves it between bottom, right and tab. The terminal uses `@xterm/xterm` 6.0.0 and
`@xterm/addon-fit` 0.11.0, both MIT (added to `package.json`; no AGPL code).

## Gaps

1. **Interrupted sessions after a reload.** A page reload abandons its session; the shell keeps
   running until the idle timeout (15 min). There is no "recent sessions" list and no re-attach by id
   yet; the count stays inside the 4-session cap.
2. **No end-to-end test of the idle sweep on a real server** — the sweep is unit-tested with a fake
   clock and a fake PTY; the 30 s timer itself is not asserted.
3. **Copy on insecure origins**: `navigator.clipboard` needs a secure context; on plain HTTP over the
   tailnet the buttons report "the browser refused the clipboard" and xterm's own selection still
   works. A fallback (`document.execCommand("copy")`) is not implemented.
4. **Desktop browsers other than Chromium/Firefox** (Safari) are not verified; the WS Origin fallback
   exists for exactly that case but is untested on a real Safari.
5. **Visual review is not mine.** Geometry and the rendered terminal text were checked; the look of
   the pane, its header and the cut corners need Agrippa's eye.
6. **R40 is only half met**: the terminal runs commands from a 390 px screen; approvals (S3) are not
   built, so the register keeps R40 `doing`.
7. The terminal is not a pack/module: its icon comes from the active pack (`terminal` role) and its
   colours from the theme tokens, but its layout constants are CSS like the rest of the shell.
