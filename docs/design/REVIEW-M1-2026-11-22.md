## 4. Ranked defects

No fixes made. Severity is my judgement, highest first.

1. **High: every write is unauthenticated for non-browser callers, token issuance included.**
   `core/csrf.ts` now stops a web page, but a local process needs no credential at all:
   `POST /api/tokens` mints an agent token, `PUT /api/settings` rewrites settings, `POST/DELETE
   /api/gateways`, `POST/DELETE /api/model-servers`, `PUT /api/plugins/:id/enabled` and
   `POST /api/chat/sessions` all succeed from plain curl with no Origin (`core/server.ts:55,97,101,110`,
   `core/gateways.ts:76,86`, `core/model-servers.ts:36,45`, `core/chat.ts:84`). Reproduced live.
   On the default `127.0.0.1` bind that is the local-process boundary and `csrf.ts` says so on
   purpose. It stops being a boundary the moment R44's tailnet access lands: add the machine's name
   to `CAESAROS_HOSTS` and every tailnet peer passes `knownHost`, sends no Origin, and gets the
   same writes, including a token. `docs/STATE.md` still discloses only "settings PUT/gateway POST",
   so the note understates the surface, and the new CSRF row reads as if writes are guarded.
2. **High: first run can report model sources that chat cannot use.** `detect()` sets
   `modelSources = engines.filter(e => e.probe.ok).length` (`core/detect.ts:178`) over Hermes,
   Claude Code, Codex and Ollama, while the engine registry ships only the Ollama adapter
   (`core/engines/index.ts:5`). Live here: `modelSources 3` with Ollama absent, so three reported
   sources and zero usable chat engines. R47's acceptance ("first run completes with one model
   source") is measured on a field that does not mean that, and `tests/server.test.ts` asserts the
   same formula, so the suite passes with the defect.
3. **Medium: the gateway probe is not size-bounded without a `Content-Length`.** `probe()` checks the
   header, then calls `await r.text()` and slices afterwards (`core/gateways.ts:56-57`), so a server
   that streams without the header is read to the end. The comment claims "bounded in time and size"
   and R44 rule 5 depends on it; `tests/gateways.test.ts` only exercises the header case.
4. **Medium: missing EN/PL strings, including raw keys rendered on screen.** `translate()` falls back
   to the key itself (`web/src/i18n.ts:532`). `Devices.tsx:106`, `ModelServers.tsx:82` and
   `Notes.tsx:138` interpolate a server error code into `…err.${err}`, but only some codes are
   translated (`i18n.ts:179-199`), so a 429 renders `devices.err.http_429`. The boot screen is
   hardcoded English (`web/src/store.tsx:124,132-135`) although `common.loading`, `error.load` and
   `error.load.body` exist and are unused. `Start.tsx:28-29` hardcodes "English"/"Polski";
   `Settings.tsx:134` hardcodes "modules" and "packs". `tests/i18n.test.ts` only checks static
   `t("…")` calls, so none of this fails the suite.
5. **Medium: R56 is not built and its evidence cell points at a screen without it.** Settings renders
   the active icon and font pack as text (`web/src/pages/Settings.tsx:128-132`) with no pickers, and
   `packs/fonts` holds only `ds0`. The register's evidence "packs/ manifests, Settings > Appearance"
   does not demonstrate "icon pack picker, at least 3 font choices".
6. **Medium: nested interactive control in the rail flyout.** The pin control is a
   `<span role="button" tabIndex={0}>` inside the row `<button>` (`web/src/shell/Flyouts.tsx`), which
   is invalid and lets the outer button swallow pointer and keyboard activation. R24 promises tap and
   keyboard behaviour on every reveal.
7. **Low: documentation drift that misstates what shipped.** R47's evidence says the first-run screen
   is not built, but `Start.tsx` exists and `/start` is the forced first route. B1 says "no module
   ships", but `plugins/hello` loads. The S2 row still says the fix is queued after `ad6efa2` landed,
   and the S3/S4 "queued" rows still read as pending next to their delivered rows. Test counts
   (23, 47, 54, 74, 117, 140) no longer match 161.
8. **Low: app shell icons are outside the pack system.** `web/index.html:11-12` links
   `/icons/mark.svg` and `/icons/apple-touch-icon.png`, and `web/public/manifest.webmanifest:13-15`
   names three more, none from a pack manifest. `tests/no-direct-assets.test.ts` scans imports in
   `web/src` only, so the R46 gate is green while "every icon is a pack" is not literally true.
9. **Low: chat can show one engine's model while sending to another, and persist it.** With an
   active session whose engine is unavailable, `engine` falls back to the first available engine and
   `chosenModel` comes from it (`web/src/pages/Chat.tsx:69-71`), the header shows
   `engine.label · chosenModel` (`:304`), but the POST carries that model to the session's own engine
   (`:156`), and the server stores it into the session when it differs
   (`core/chat.ts:126,136-141`). The transcript can name a model the reply did not use.
10. **Low: two tests overclaim what they assert.** "a fresh install has no gateway, no owner host and
    one local engine" reads `/api/settings` only and never `/api/engines` (`tests/server.test.ts:27-35`).
    "a pack with a broken manifest is skipped, not guessed at" calls `missingRoles`, not the loader
    (`tests/packs.test.ts:55-58`). And `tests/seg-targets.test.ts` measures CSS text, never a rendered
    height, which STATE itself admits.
11. **Low: the notes and terminal operator check rests on browser headers.** `browserLike()` needs
    `Sec-Fetch-Site` in `same-origin|same-site|none` (`core/principal.ts`), so a browser that omits it
    is refused on operator-only routes. STATE flags iPhone Safari as untested; until it is tested,
    "operator only" is proven for Tauri/WebKitGTK and desktop browsers, not for every client.
