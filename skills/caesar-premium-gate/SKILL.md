# Premium gate

"Premium" is a result you can point at, not a mood. The method comes from the OMH design-quality-gate workflow, restated for CAESAR.

## The gate
1. **Name the bar**: the surface (web, phone, deck, PDF, video), the audience, and one or two references it must beat (a competitor, the best thing the user showed, CAESAR's own best page). Without a reference there is no "premium", only "not broken".
2. **Rubric, five lines**: content (is every sentence earning its place), hierarchy (one clear thing first), layout and spacing, craft details (type, alignment, states, motion), accessibility (contrast, focus, reduced motion, tap targets). Score each: beats the bar, meets it, below it.
3. **Evidence**: render it and look. Web: screenshots at 428 px and desktop, real data and the worst case (long names, empty, many). Video: the final encoded file at delivery size. A plan or a code review is not evidence of how it looks.
4. **The style layer**: CAESAR style for the owner's own work, the client's kit for a client (see `caesar-grill-me`). A client deliverable in the wrong style is below the bar whatever its polish.
5. **Fix the weakest first**, re-render, re-judge. Two rounds, then deliver or ask.

## States, kept apart
prepared (a plan) -> generated (files exist) -> checked (you looked, with the screenshots named) -> approved (the user said yes) -> published (only the user does it). Report the highest state you can prove.

## CAESAR's own tells that fail the gate
Native browser controls, emoji as icons, stock-looking fields, unstyled disclosure triangles, text that wraps badly on a phone, a screen never viewed on a phone, empty states with no words, colours that are not theme tokens, a page that works only with a mouse.

## Report
A short table: what changed, where to see it, what to test. Say what you did not check.
